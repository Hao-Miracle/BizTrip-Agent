# BizTrip Reimbursement Audit

Use the host Agent's existing language model to understand the user's request and explain the audit. Use the local BizTrip engine only to read email, parse evidence, calculate totals, and identify gaps. This Skill is a reimbursement audit, not the complete package generator.

## Boundaries

- Never request, read, print, transmit, or edit email authorization codes, passwords, API keys, or `.env` values.
- Never ask the user to configure another model URL, API key, or model name for this audit. The host Agent already provides the reasoning layer.
- Never invent or silently repair an amount, date, vendor, attachment, duplicate decision, or trip assignment.
- Never claim that an Excel workbook or final reimbursement package was generated by the audit.
- Keep reimbursement evidence local. Do not upload attachments to another service.
- Explain that the local personal app is required only when the user wants a complete Excel workbook and organized originals.

## Locate the Engine

Use the first available command:

1. `biztrip`
2. `.venv/bin/biztrip` from a BizTrip Agent checkout
3. `python -m biztrip_agent.cli` from an installed environment

If none is available, run the bundled installer in check mode:

```bash
python <SKILL_DIR>/scripts/install_engine.py --check
```

Resolve `<SKILL_DIR>` from this `SKILL.md` location. Do not assume the user's current working directory.

If it returns `not_installed`, explain that the free local audit engine must be installed to read the user's mailbox locally. Ask for permission before downloading or installing anything. After approval, run:

```bash
python <SKILL_DIR>/scripts/install_engine.py
```

Parse its single JSON result and use `engine_command` for later commands. Never install without explicit approval, request administrator access, modify system Python, or replace an existing installation.

If Python is unavailable or below 3.8, show the returned requirement and direct the user to `https://www.python.org/downloads/`. Do not execute an untrusted third-party installer.

## Run the Audit

Convert the user's request into one of these bounded scans:

```bash
biztrip agent audit --start YYYY-MM-DD --end YYYY-MM-DD
```

The date range may cover at most 31 calendar days. If the user asks only to inspect recent email, use at most 60 messages:

```bash
biztrip agent audit --count 60
```

If the requested range is unclear, ask one concise question. Parse stdout as one JSON object.

If the result is `setup_required`, launch the returned engine command with `web`. Ask the user to save only their mailbox address and email authorization code in the local page, then retry once. Do not ask them to configure the personal app's Agent model for a Skill audit.

## Present the Audit

For `audit_ready`, explain in plain language:

- Estimated record count, trip count, and total amount.
- Expense categories and their amounts.
- Detected trips.
- Missing fields, missing originals, conflicts, or other issue codes.
- Whether the returned record preview was truncated.

Treat all figures as an audit estimate until the complete package passes final verification. Do not expose local task paths or internal JSON to ordinary users.

End with the next useful choice: the audit has not generated Excel or copied originals; the user can open the free local personal app to resolve details and generate the complete reimbursement package. Do not describe this as a failure.

For `failed`, explain the returned message without repeated retries. Never ask the user to paste secrets into chat.
